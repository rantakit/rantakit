# v0.2 Foundation: stories

The stories for [v0.2 Foundation](../../ROADMAP.md#v02-foundation), grouped by epic in the order they are built. Each story is a vertical slice that can be tested on its own. Product rules come from [RANTAKIT.md](../../RANTAKIT.md), words from [GLOSSARY.md](../../GLOSSARY.md), and code boundaries from [ARCHITECTURE.md](../../ARCHITECTURE.md).

Every story has acceptance criteria, the layers it touches, the screens and states it needs designed, and its platforms. v0.2 is desktop only (Windows and Linux), so every story below is **Platforms: Windows, Linux** unless it says otherwise.

Decisions made while writing these stories (2026-11-01):

- Kompres Foto, Ubah Format Foto (convert photo), and Ubah Ukuran Foto (resize photo) become three Tools; v0.1.0 had them as options of one screen.
- With several files, a Size limit applies to each file.
- History starts empty in v0.2; the v0.1.0 `history.json` is not carried over.
- Settings is a medium-to-large dialog inside the main window.
- On desktop, the Result offers Share only on Windows.
- The in-app update check is postponed while the maintainer is the only user.
- Translations live in typed dictionaries (`id.ts`, `en.ts`) with a `t()` helper.
- Colors are design tokens; their light and dark values are in N1.
- The engine contract types live in a small shared crate, `rantakit-core`, so `rantakit-pdf` does not depend on `rantakit-image`. The name follows the Rust `*-core` convention (`rand_core`, `futures-core`); unlike the old `rantakit_core`, it holds no file-format code.

Decisions made after 0.2.0-rc.1 (2026-11-02), shipped in 0.2.0-rc.2:

- Windows and Linux draw Rantakit's own title bar (W1), which carries Back, Forward, and a button to hide the sidebar (W2, W3). The in-app "⋯" menu is removed; its commands are keyboard shortcuts, and the license and source code links stay in Settings, "Tentang".
- The sidebar gets "Buka" (Open), the picker version of a drop (H6).
- The Tool page fills the window, with Options as a panel on its right edge (L1, L3).

## 1. Engine foundation

### E1. Split the engine into `rantakit-image` and `rantakit-pdf`

**Capability:** the image and PDF engines live in their own Tauri-free crates, so each can grow and be measured on its own ([ADR 0004](../adr/0004-engines-and-tasks-in-tauri-free-crates.md)).

**Acceptance criteria**
- `crates/rantakit_core` is replaced by `crates/rantakit-image` and `crates/rantakit-pdf`; the app behaves exactly as before.
- Existing tests and fixtures move with their engine and pass.
- Neither crate depends on Tauri.

**Layers:** `rantakit-image`, `rantakit-pdf`, `src-tauri` (imports)
**Screens and states:** none

### E2. One engine contract: files, progress, cancel, error kinds

**Capability:** every engine function follows the [engine contract](../../ARCHITECTURE.md#engine-contract).

**Acceptance criteria**
- A new Tauri-free crate, `rantakit-core`, holds what every engine shares: the error kinds, progress, the cancel token, and writing a Result safely. It holds no file-format code.
- Engines take a local input path and write the Result to an output path they are given. They never write over an existing file.
- Engines report progress through a callback, as a fraction that only goes up and ends at 1. Engines that work page by page may report page *n* of *m* instead; Kompres PDF reports a fraction, because it works through the images in a PDF, not its pages.
- Engines check the cancel token between steps, at least before every encode, so they stop within about a second. A cancelled or failed file leaves no partial Result: the Result is written to a temporary file next to it and renamed only when complete.
- Engines return typed error kinds: `PasswordProtected`, `Damaged`, `UnsupportedFormat`, `SizeLimitUnreachable { best }`, `NotEnoughSpace`, `CannotWrite`, `OriginalMissing`, and `Cancelled`. `Cancelled` is an outcome, not a problem, so it has no message in I3. An encoder failure inside an engine is reported as `Damaged`.
- Engines detect a file's kind from its content, not its extension.
- Every error kind an engine can return, cancelling, and progress have a test.

**Layers:** `rantakit-core`, `rantakit-image`, `rantakit-pdf`, `src-tauri` (calls)
**Screens and states:** none

### E3. `rantakit-tasks` runs Tasks and names Results

**Capability:** one Tauri-free crate owns the rules that make a Task safe, for every platform.

**Acceptance criteria**
- A Task runs one Tool over one or more files. A failed file does not stop the others; each file ends with its Result or its error kind.
- Results get the new names from [RANTAKIT.md](../../RANTAKIT.md#where-results-go-and-what-they-are-called), for example `ijazah (compressed).pdf`, then `ijazah (compressed) (2).pdf` when the name is taken.
- The Original is never modified, moved, or overwritten. Tests prove it for every Tool.
- A Result goes next to its Original, or into the Results folder chosen in Settings.
- If the folder cannot be written to, the file ends with `CannotWrite`.

**Layers:** `rantakit-tasks`
**Screens and states:** none

### E4. Tool catalogue facts and file matching

**Capability:** `rantakit-tasks` knows every Tool's facts and which Tools fit a set of files.

**Acceptance criteria**
- Each Tool has an id, a Job group, the file kinds it accepts, its platforms, and whether it has shipped or is coming soon.
- The catalogue lists every Tool planned before 1.0 ([RANTAKIT.md §4](../../RANTAKIT.md#4-tool-catalogue)).
- Given dropped files, it returns the shipped Tools that accept all of them.
- Names, descriptions, and icons are not in Rust; the frontend owns them.

**Layers:** `rantakit-tasks`
**Screens and states:** none

### E5. Thin shell with progress and cancel

**Capability:** `src-tauri` only adapts requests to `rantakit-tasks`.

**Acceptance criteria**
- One command starts a Task and returns its id; progress and per-file outcomes reach the frontend as events.
- A command cancels a running Task.
- Errors reach the frontend as error-kind codes, never as English text.
- Result naming and History code are gone from `src-tauri`.

**Layers:** `src-tauri`, frontend API layer
**Screens and states:** none

### E6. CI on every push

**Capability:** mistakes are caught before a release.

**Acceptance criteria**
- A workflow runs the Rust tests and the frontend type check on every push and pull request, on Windows and Linux.
- A missing translation key fails the type check (see I1).

**Layers:** `.github/workflows`
**Screens and states:** none

### N2. Fonts and text size

As an older user, I can read every screen comfortably.

**Acceptance criteria**
- Fredoka is used for the wordmark, page titles, and large headings only; Plus Jakarta Sans for everything else.
- Both fonts are bundled with the app; nothing is downloaded.
- Base text size is 16 px.
- Settings offers a text size choice, replacing v0.1.0's UI zoom. "Besar" multiplies every text style by 18/16 and "Lebih besar" by 20/16.
- Every text uses one of six styles (size / line height in px):

| Style | Font | Size | Used for |
|---|---|---|---|
| Page title | Fredoka 600 | 32 / 40 | Top of Home and Tool pages, the drop overlay |
| Dialog title | Fredoka 600 | 26 / 34 | Dialog titles, the Result summary, the large Result size |
| Section | Plus Jakarta Sans 700 | 18 / 26 | Section headings, file count |
| Body | Plus Jakarta Sans 400 | 16 / 24 | Normal text; Tool card names at 600 |
| Label | Plus Jakarta Sans 600 | 15 / 22 | Buttons, sidebar, tabs, file names |
| Small | Plus Jakarta Sans 400 or 500 | 14 / 20 | Hints, sizes, notes, badges, messages |

- The sidebar wordmark (Fredoka 600, 22 / 28) is part of the logo, not a text style.

**Layers:** frontend
**Screens and states:** typography scale; Settings text size

### N3. Icons

As a user, I recognize each Tool by its icon and its name.

**Acceptance criteria**
- Keyline Icons, rounded variant, replace the current icon set.
- Styles follow [RANTAKIT.md §8](../../RANTAKIT.md#icons): stroke by default, fill for the active sidebar item and selected options, duotone teal for Tool icons on Home and at the top of a Tool page.
- Every Tool and navigation icon has a text label next to it.
- Four sizes: 16 px inside links, 20 px in buttons and rows, 24 px in the sidebar and on Tool cards, 40 px at the top of a Tool page. The selected Settings tab uses fill, like the selected sidebar item.

**Layers:** frontend
**Screens and states:** icon set; sidebar active and inactive

### N4. Building blocks

As a user, I find every button, row, and card behaving the same way on every screen.

**Acceptance criteria**
- Buttons come in four kinds:
  - **Primary:** teal fill, at most one per screen
  - **Secondary:** surface with a `border-strong` border
  - **Danger:** red fill, only inside a confirmation dialog
  - **Text link:** teal text without a box, underlined on hover
- Main actions are 48 px tall and actions inside a row 40 px. Each kind has default, hover (background change only, no shadow), keyboard focus, and disabled (`badge-bg` with `text-disabled`) states; the Primary button also has a working state with a spinner before its label.
- Every focusable item (buttons, cards, tabs, rows, inputs, switches) shows the same focus ring for keyboard focus: 3 px `brand-strong`, 2 px away from the item.
- Sidebar items are 44 px tall: default, hover (`badge-bg`), selected (`brand-soft` with `brand-strong` text and a fill icon), keyboard focus.
- A Tool card has default, hover (`brand` border), keyboard focus, and Coming soon (H2) states.
- A file row in the Files step shows its state: ready (size and a remove button), waiting ("Menunggu"), working (percentage and progress bar), done (green check, "Selesai · 196 KB"), skipped (grey check, for example "Sudah JPG, tidak diubah"), or failed (red icon and message).
- A problem row in the Result has a soft background, an icon, the message, and its action: red with "Coba lagi" for a failed file, amber with "Ya, kecilkan" for a Size limit not reached, grey for a cancelled file. Color is never the only signal.

**Layers:** frontend
**Screens and states:** Building blocks board (light and dark)

## 3. English

### I1. Typed translations

**Capability:** every string the user reads comes from a dictionary.

**Acceptance criteria**
- `id.ts` and `en.ts` hold every string, with keys checked at compile time and `{name}` placeholders.
- A `t()` helper returns the string for the current language.
- A key missing from either language fails the type check.

**Layers:** frontend
**Screens and states:** none

### I2. Choose a language

As an English-speaking user, I can use Rantakit in English.

**Acceptance criteria**
- The language follows the operating system by default.
- Settings offers "Ikuti sistem" (Follow system), Bahasa Indonesia, and English, and switching is instant.
- Every screen is fully translated, in plain, warm wording that follows the GLOSSARY.md rules in both languages.
- No word from the GLOSSARY.md "Words never shown by default" list appears outside Advanced options.

**Layers:** frontend
**Screens and states:** Settings language choice; every screen in English

### I3. Error messages that say what to do next

As a user, when a file fails, I know why and what to do.

**Acceptance criteria**
- Each error kind has one message in each language:

| Error kind | Indonesian | English |
|---|---|---|
| `PasswordProtected` | "PDF ini dikunci dengan kata sandi. Buka kuncinya dulu, lalu coba lagi." | "This PDF is locked with a password. Unlock it first, then try again." |
| `Damaged` | "File ini rusak atau tidak lengkap. Coba unduh atau salin ulang filenya." | "This file is damaged or incomplete. Try downloading or copying it again." |
| `UnsupportedFormat` | "Peralatan ini belum bisa membuka file jenis ini." + accepted formats | "This tool can't open this kind of file yet." + accepted formats |
| `SizeLimitUnreachable { best }` | "Paling kecil bisa {best}. Kecilkan juga ukuran gambarnya?" + button | "Can only reach {best}. Also shrink the image dimensions?" + button |
| `NotEnoughSpace` | "Ruang penyimpanan penuh. Kosongkan sedikit ruang, lalu coba lagi." | "Storage is full. Free up some space, then try again." |
| `CannotWrite` | "Hasil tidak bisa disimpan di folder ini. Pilih folder lain di Pengaturan." | "The Result can't be saved in this folder. Choose another folder in Settings." |
| `OriginalMissing` | "File aslinya sudah dipindah atau dihapus." | "The original file was moved or deleted." |

- `Cancelled` has no message; the file is marked "Dibatalkan" (L2).
- A password field for locked PDFs can come later; v0.2 only explains.

**Layers:** frontend
**Screens and states:** error row in the Result list; `SizeLimitUnreachable` with its follow-up button

## 4. Home screen

### H1. All tools, grouped by Job

As a user, I see every Tool in a few clear groups.

**Acceptance criteria**
- "Semua peralatan" (All tools) groups Tools by Job: *Kecilkan & Ubah* (Shrink & Convert), *Scan*, *Atur PDF* (Arrange PDF), *Ambil Teks* (Get Text), *Bagikan dengan Aman* (Share Safely).
- Each Job is a section with a heading, all on one scrolling page (no tabs).
- Each Tool card shows its icon, name, and one-line description.

**Layers:** frontend, `rantakit-tasks` (catalogue)
**Screens and states:** Home (first launch, after use)

### H2. Coming soon cards

As a user, I can see which Tools are on their way.

**Acceptance criteria**
- Tools planned before 1.0 but not built yet appear in All tools and in search, greyed out with a "Segera hadir" (Coming soon) badge.
- They come after the shipped Tools in their Job section. The badge is a small pill in the card's top-right corner, and the faded description stays visible.
- They cannot be clicked and show no message.
- A screen reader reads them as "<Tool name>, segera hadir".
- Android-only Tools (Scan Dokumen) do not appear on desktop.
- Tools listed as Later in RANTAKIT.md never appear.

**Layers:** frontend, `rantakit-tasks` (catalogue)
**Screens and states:** coming soon card

### H3. Recent tools

As a returning user, the Tools I use most are one click away.

**Acceptance criteria**
- "Terakhir dipakai" (Recent tools) shows the last 4 Tools used, newest first, above All tools, as one row of cards bigger than the All tools cards.
- It is hidden until the first Task finishes.

**Layers:** frontend, `rantakit-tasks`
**Screens and states:** Home with Recent tools

### H4. Search

As a user, I find a Tool by typing what I want to do.

**Acceptance criteria**
- Search matches Tool names and descriptions in both Indonesian and English, whatever the UI language, ignoring case.
- "kompres" finds Kompres Foto and Kompres PDF; "jpg ke png" or "convert" finds Ubah Format Foto; "resize" finds Ubah Ukuran Foto.
- The search box sits at the top of the Home content and filters the Tool grid in place as the user types.
- No match shows an icon and a title only, for example "Peralatan tidak ditemukan" (No Tool found).

**Layers:** frontend
**Screens and states:** search results; no results

### H5. Drop files to see the Tools that fit

As a user, I drop files on the window and Rantakit shows what it can do with them.

**Acceptance criteria**
- While files are dragged over Beranda (Home) or Riwayat (History), an overlay says "Lepas di sini · 3 foto" (Drop here · 3 photos).
- Dropping them opens a dialog titled "Mau diapakan 3 foto ini?" (What should we do with these 3 photos?). It shows the file names and lists only the shipped Tools that accept all of them. The dialog appears even when only one Tool fits.
- Choosing a Tool opens it with the files already added. "Batal" (Cancel) closes the dialog and keeps nothing.
- Dragging files onto a Tool page adds them to that Tool: "Lepaskan untuk menambahkan ke Kompres Foto" (Drop to add to Kompres Foto). No dialog.
- Files no Tool accepts are refused during the drag, not after: "Rantakit belum bisa membuka file jenis ini" (Rantakit can't open this kind of file yet), with "Apa yang bisa: JPG, PNG, PDF" (What works: JPG, PNG, PDF). The drop is ignored. This is the `UnsupportedFormat` message.
- Photos and PDFs dragged together are refused the same way: "Foto dan PDF tidak bisa diproses bersamaan. Seret foto saja atau PDF saja." (Photos and PDFs can't be processed together. Drag only photos or only PDFs.)

**Layers:** frontend, `src-tauri`, `rantakit-tasks` (matching)
**Screens and states:** drop overlay; matching Tools; one Tool fits; nothing fits; photos and PDF together; drop on a Tool page

### H6. Buka: choose files, then a Tool

As a user who doesn't drag files, I start from the files I have, not from a Tool.

**Acceptance criteria**
- "Buka" (Open) sits at the top of the sidebar, in the primary color, above Beranda.
- It opens the system file picker for photos and PDFs ("Pilih file", filter "Foto dan PDF"), several files at once.
- The chosen files go the same way as a drop (H5): on Beranda or Riwayat the "Mau diapakan…" dialog; on a Tool page they are added to that Tool.
- Chosen files that don't fit get the drop's words in a dialog, since there is no drag to show them on: "Foto dan PDF tidak bisa diproses bersamaan" (Photos and PDFs can't be processed together) with "Pilih file lain" (Choose other files), which opens the picker again, and "Tutup" (Close).
- On phones, "Buka" waits for v0.3, where files come from the Android share sheet.

**Layers:** frontend
**Screens and states:** sidebar with "Buka"; chosen files that don't fit

## 5. Three-step Tool layout

### L1. Files and Options

As a user, every Tool works the same way: add files, check the options, press one button.

**Acceptance criteria**
- **Files:** pick from the system file picker or drop; each file shows a thumbnail, size, and page count for PDFs; files can be removed before starting.
- **Options:** defaults are already filled in, Advanced options are collapsed, and there is one main button ("Kompres" (Compress), "Ubah" (Convert), …).
- The app remembers whether the user left Advanced options open, per Tool.
- On desktop, the Tool page fills the content card and never scrolls as a whole. Files are a flexible column on the left; Options are a panel on the card's right edge (320 px, 360 px from 1024 px wide), tinted like the Settings panel and set off by a line, with the main button at its foot. The file list and the Options each scroll on their own; the file count stays at the top of the list and "Tambah foto" (Add photos) at its foot. The sidebar stays, unless the user hid it (W3).
- The page starts with one short row: the Tool icon on its tint and the Tool name. Back is in the title bar (W2); on phones, which have no title bar, the row starts with a back button to Beranda.
- On phones, Files and Options stack and the page scrolls, with the main button pinned above the tab bar.
- Each Tool names its files in its own words: "foto" in the photo Tools ("3 foto", "Pilih foto", "Tambah foto"), "PDF" in the PDF Tools ("2 PDF", "Pilih PDF").
- **Empty:** the Files column is one drop zone with a "Pilih foto" (Choose photos) button, "atau seret ke sini" (or drag here), and the accepted formats. Options already show their defaults; the main button is disabled with "Tambahkan foto dulu" (Add photos first).
- **With files:** one row per file (thumbnail, name, size, remove button), then "Tambah foto" (Add photos).
- Advanced options are labelled "Pilihan lanjutan" (More options), never "Pengaturan", which is the app's Settings.
- An option whose name needs explaining, such as "Ukuran gambar" (Image size) or "Kualitas" (Quality), has a "?" button right after its label. Hovering, focusing, or tapping it shows a short popover in plain words; tapping again, moving away, or Escape closes it.
- Leaving a Tool page that has files added asks first: "Tinggalkan halaman ini?" (Leave this page?), with "Tetap di sini" (Stay here) as the default and "Tinggalkan" (Leave). Back, the sidebar, and Escape all ask. An empty page or a Result leaves without asking.

**Layers:** frontend
**Screens and states:** Tool page empty; with files; Advanced options open; leave with files added

### L2. Working, with Cancel

As a user, I see progress and can stop a Task.

**Acceptance criteria**
- While a Task runs, each file shows its progress: a progress bar, "Menunggu" (Waiting), or "Selesai" (Done) with its new size. Options are locked, and the main button is replaced by "Mengompres 2 dari 3 foto…" (Compressing 2 of 3 photos…) and "Batalkan" (Cancel).
- A Cancel button stops the Task; finished Results stay, and the unfinished file leaves nothing behind.
- After Cancel, the Result view says "Dibatalkan · 1 dari 3 foto selesai" (Cancelled · 1 of 3 photos done); unfinished files are marked "Dibatalkan" with no actions.
- Leaving while a Task runs asks "Hentikan dan keluar?" (Stop and leave?), with "Lanjutkan" (Keep going) as the default and "Hentikan" (Stop).

**Layers:** frontend, `src-tauri`
**Screens and states:** working; cancelled; leave while working

### L3. Result

As a user, I see what I got and can use it right away.

**Acceptance criteria**
- Each file shows its size before and after and a preview.
- Actions: **Buka** (Open) and **Tampilkan di folder** (Show in folder); **Bagikan** (Share) opens the system share sheet on Windows only.
- The Result keeps the Tool page's layout: the Results on the left, and in the right panel a summary ("3 foto selesai" (3 photos done)) and where the Results were saved, with "Proses file lain" (Process another file) at its foot.
- Many files: one row per Result with its name, "1,8 MB → 196 KB", and "Di bawah 200 KB" (Under 200 KB) when a Size limit was used. One file: a large preview with the sizes and the same actions.
- A failed file shows its message from I3 and a "Coba lagi" (Try again) button; other files are unaffected.
- Failed files are marked red and a Size limit that was not reached is marked amber, each always with an icon and text:

| Token | Light | Dark |
|---|---|---|
| danger / danger-soft | `#B91C1C` / `#FEF2F2` | `#F87171` / `#3B1717` |
| warn / warn-soft | `#B45309` / `#FFFBEB` | `#FBBF24` / `#3A2A0E` |

- "Proses file lain" (Process another file) returns to an empty Tool page.

**Layers:** frontend, `src-tauri`
**Screens and states:** Result (all succeeded, some failed, one file, many files)

## 6. Tools

### T1. Kompres Foto

As a job applicant, I make a photo small enough for a portal.

**Acceptance criteria**
- Accepts JPG and PNG.
- Main options: *Sesuaikan batas ukuran* (default) and *Kecilkan saja* (see C1, C2).
- Advanced options: output format (same as the Original, JPG, or PNG); longest side (plain choices); exact quality number 1–100, which overrides the choice.
- Results are named `foto (compressed).jpg`.

**Layers:** `rantakit-image`, `rantakit-tasks`, frontend
**Screens and states:** Kompres Foto page (all L1–L3 states)

### T2. Ubah Format Foto

As a user, I turn a PNG into a JPG (or the other way) because a portal asks for it.

**Acceptance criteria**
- Accepts JPG and PNG; main option: to JPG or to PNG, as two radio cards labelled "JPG" and "PNG" under the heading "Ubah ke" (Convert to), with no description.
- The default is the opposite of the files' current format. A file already in the chosen format is skipped and says "Sudah JPG, tidak diubah" (Already JPG, not changed).
- Advanced options, shown only when converting to JPG: JPG quality (default 90, with a "?" explanation); background color when a transparent PNG becomes JPG: "Putih" (White, default), "Hitam" (Black), or "Pilih warna" (Choose color).
- The main button is "Ubah" (Convert).
- Results are named `foto (converted).jpg`.
- The final Tool name is checked against search vocabulary ("ubah jpg ke png", "konversi foto") before release.

**Layers:** `rantakit-image`, `rantakit-tasks`, frontend
**Screens and states:** Ubah Format Foto page

### T3. Ubah Ukuran Foto

As a user, I make a photo's dimensions smaller without thinking in pixels.

**Acceptance criteria**
- Accepts JPG and PNG; main options: *Besar* (Large, 1920 px), *Sedang* (Medium, 1280 px, default), *Kecil* (Small, 800 px), shown by name only, as radio cards with one line each: "Tetap jelas di layar besar", "Pas untuk dikirim lewat WhatsApp", "Pas untuk formulir online".
- Advanced options: exact longest side in px ("Sisi terpanjang (px)", with a "?" explanation), which overrides the choice.
- Photos are never enlarged; a photo already smaller says "Sudah kecil, tidak diubah" (Already small, not changed).
- The main button is "Ubah ukuran" (Resize).
- Results are named `foto (resized).jpg`.
- The final Tool name is checked against search vocabulary ("kecilkan ukuran foto", "resize") before release.

**Layers:** `rantakit-image`, `rantakit-tasks`, frontend
**Screens and states:** Ubah Ukuran Foto page

### T4. Kompres PDF

As a CPNS applicant, I make my ijazah (diploma) PDF fit the portal's limit.

**Acceptance criteria**
- Accepts PDF.
- Main options: *Sesuaikan batas ukuran* (default) and *Kecilkan saja* (see C1, C2).
- Each file row shows the page count and size ("3 halaman · 3,4 MB").
- Advanced options: image quality number ("Kualitas gambar (1–100)"); maximum image resolution ("Resolusi gambar maksimum": unchanged, 300, 200, 150, or 100 dpi). Both have a "?" explanation.
- Text and vector graphics stay untouched, as in v0.1.0. Options say so: "Teks tetap tajam. Hanya gambar di dalam PDF yang dikecilkan." (Text stays sharp. Only the images inside the PDF get smaller.)
- A password-protected PDF ends with `PasswordProtected`.
- Results are named `ijazah (compressed).pdf`.

**Layers:** `rantakit-pdf`, `rantakit-tasks`, frontend
**Screens and states:** Kompres PDF page

## 7. Compression by outcome

### C1. Fit a size limit

As a CPNS applicant, I type the size limit from the portal ("200 KB") and Rantakit makes my file fit, so the portal accepts it.

**Acceptance criteria**
- *Sesuaikan batas ukuran* is the default mode for Kompres Foto and Kompres PDF.
- The limit is typed with a KB/MB unit; with several files, it applies to each file.
- Each Result is at or under the limit, at the best quality that fits. For PDFs, the engine searches image quality and resolution until the file fits.
- A two-part switch at the top of Options picks "Sesuaikan batas ukuran" or "Kecilkan saja". The limit field has a KB/MB unit and is filled with the last limit used. On first use it is empty with "Kosongkan kalau tidak ada batas" (Leave empty if there's no limit), and an empty limit compresses like *Seimbang*, so one press of the main button still works.
- If the limit cannot be reached, the file ends with `SizeLimitUnreachable`, showing how close it got and offering to shrink the image dimensions too. No Result is saved for that file; "Ya, kecilkan" (Yes, shrink it) runs only that file again with smaller dimensions.
- The Original is untouched.

**Layers:** `rantakit-image`, `rantakit-pdf`, `rantakit-tasks`, frontend
**Screens and states:** Options with size field; limit not reached

### C2. Just make it smaller

As a user without a limit to meet, I pick how small I want it in plain words.

**Acceptance criteria**
- *Kecilkan saja* offers *Paling kecil* (Smallest), *Seimbang* (Balanced, default), and *Paling jernih* (Clearest), as radio cards with one line each: "File paling hemat", "Pilihan aman untuk kebanyakan foto", "Foto tetap tajam".
- The choices map to these settings, kept in one place in `rantakit-tasks`, to be tuned with real documents before release:

| Choice | Photos | PDF |
|---|---|---|
| *Paling kecil* | JPG quality 60, longest side ≤ 1600 px | image quality 50, ≤ 150 dpi |
| *Seimbang* | quality 75, ≤ 2560 px | quality 70, ≤ 200 dpi |
| *Paling jernih* | quality 88, original size | quality 85, original resolution |

- The 1–100 quality number appears only in Advanced options.

**Layers:** `rantakit-tasks`, frontend
**Screens and states:** Options with the three choices

## 8. Size limits and Presets

### S1. Recent Size limits

As a user who uses the same portal often, I don't retype the limit.

**Acceptance criteria**
- The last 5 Size limits typed are offered as quick choices next to the field, newest first, without duplicates.
- They are shared between Kompres Foto and Kompres PDF.

**Layers:** `rantakit-tasks`, frontend
**Screens and states:** size field with quick choices

### S2. Presets

As a user, I save my settings for a portal under a name I choose.

**Acceptance criteria**
- In a Tool's Options, the user can save the current options as a Preset with a name ("Pas foto CPNS: JPG, 200 KB" (CPNS ID photo: JPG, 200 KB)).
- Presets are listed in that Tool's Options; choosing one fills in its options.
- The Preset picker sits at the top of Options and shows "Tanpa preset" (No preset) by default. "Simpan sebagai preset" (Save as preset) sits above the main button.
- Presets can be renamed and deleted from "Kelola preset" (Manage presets) at the bottom of the picker, which opens a small dialog.
- Rantakit ships no Presets of its own ([ADR 0003](../adr/0003-no-institution-presets.md)).

**Layers:** `rantakit-tasks`, frontend
**Screens and states:** Preset list; save Preset; rename and delete

## 9. Riwayat

### R1. Riwayat page

As a user, I find a file I made earlier and use it again.

**Acceptance criteria**
- "Riwayat" (History) replaces the "Terbaru" (Latest) page in the sidebar.
- Each entry shows the Tool, date, file names, and size before and after.
- Entries are grouped by day ("Hari ini" (Today), "Kemarin" (Yesterday), then the date). One entry is one Task: Tool icon and name, time, file names ("KTP (compressed).jpg dan 2 lainnya" (and 2 more)), and total size before → after.
- Each entry offers Open and Show in folder; a Result that was moved or deleted is marked as missing.
- A Task with one file shows **Buka** and **Tampilkan di folder**. A Task with several files shows **Tampilkan di folder** and "Lihat 3 file" (See 3 files), which expands one row per Result, each with its own **Buka**.
- A missing Result is greyed out with "File hasil sudah dipindah atau dihapus" (The Result file was moved or deleted) and has no actions. There is no per-entry delete in v0.2.
- The page title is followed by "Disimpan 30 hari. File hasilnya tidak ikut terhapus." (Kept for 30 days. Your Result files are not deleted.)
- Empty Riwayat shows an icon, "Belum ada riwayat" (No history yet), and "Hasil dari setiap peralatan akan muncul di sini." (Results from every Tool will show up here.)
- History starts empty in v0.2, and the old `history.json` is removed on first launch. Results made by v0.1.0 stay on disk.

**Layers:** `rantakit-tasks`, `src-tauri`, frontend
**Screens and states:** Riwayat (empty, with entries, missing Result)

### R2. Keeping and clearing History

As a privacy-minded user, I decide whether Rantakit remembers my Tasks.

**Acceptance criteria**
- Entries older than 30 days are removed automatically.
- **Hapus riwayat** (Clear history) removes all entries in one click; the page says plainly that the Results themselves are not deleted.
- It asks first: "Hapus semua riwayat?" (Clear all history?), "Daftar ini akan dikosongkan. File hasil yang sudah tersimpan tidak ikut terhapus." (This list will be emptied. Result files you've saved are not deleted.) "Batal" (Cancel) is the default; "Hapus riwayat" is red.
- With History off, Riwayat says "Riwayat sedang dimatikan" (History is turned off) and "Rantakit tidak mencatat tugas apa pun sampai riwayat dinyalakan lagi." A "Nyalakan riwayat" (Turn on history) button turns it on right there.
- **Simpan riwayat** (Keep history) in Settings is on by default; turning it off clears History and records nothing more until it is turned on again.
- Recent tools (H3) keep working when History is off.

**Layers:** `rantakit-tasks`, frontend
**Screens and states:** clear History confirmation; Riwayat with History off

## 10. Settings

### ST1. Settings dialog

As a user, I change how Rantakit behaves without leaving what I'm doing.

**Acceptance criteria**
- Settings opens as a medium-to-large dialog inside the main window from the sidebar; the separate Settings window is removed.
- It contains:
  - Theme: light, dark, follow system (N1), and text size (N2)
  - Language: Ikuti sistem, Bahasa Indonesia, English (I2)
  - Results folder: next to the Original (default), or a chosen folder
  - Simpan riwayat (R2)
  - About: version, license, and link to the source code. No donation line in v0.2.
- The dialog is about 800 × 560 px, titled "Pengaturan", with a fixed height so switching tabs does not resize it. No Save button.
- Sections are vertical tabs on the left, each with an icon: "Tampilan" (Appearance), "Bahasa" (Language), "File hasil" (Result files, whose panel is headed "Tempat menyimpan hasil", Where Results are saved), "Riwayat", and "Tentang" (About). The selected tab is marked like the selected sidebar item, and the arrow keys move between tabs.
- The tab's content sits on a panel tinted differently from the dialog (light `#F9FAFB`, dark `#151515`), so the tabs and their content read as two areas.
- "Tentang" shows the Rantakit logo with "Rantakit" and "Versi 0.2.0" above the license and the source code link.
- Theme and text size are three-part switches: "Ikuti sistem" (default), "Terang", "Gelap"; "Normal" (16 px, default), "Besar" (18 px), "Lebih besar" (20 px). A sample line shows the chosen text size.
- Language is a radio list, each language named in itself; "Ikuti sistem" shows the current one, "(sekarang Bahasa Indonesia)".
- Results folder is a radio choice: "Di sebelah file aslinya" (default) or "Di folder pilihan", which shows the path and "Ganti folder" (Change folder).
- Turning off "Simpan riwayat" asks first: "Matikan riwayat?", "Riwayat yang ada akan dihapus. File hasil tidak ikut terhapus.", with "Batal" as the default and "Matikan" in red.
- The update check switch arrives with the update check itself, not in v0.2.
- Every change applies immediately and is remembered.
- The dialog closes with Escape and can be used with the keyboard alone.

**Layers:** frontend, `rantakit-tasks` (Results folder, History switch)
**Screens and states:** Settings dialog (light and dark): each tab (Tampilan, Bahasa, File hasil with a chosen folder, Riwayat, Tentang); turn off History confirmation

## 11. Window and navigation

### W1. Rantakit's own title bar

As a user, the window looks like one piece with the app, not an app inside an OS frame.

**Acceptance criteria**
- On Windows and Linux the OS title bar is gone; Rantakit draws a 36 px bar in the window background color. On macOS the system's traffic lights stay, and Rantakit's buttons start right of them.
- The bar holds, from the left: hide the sidebar, Back, Forward (W2, W3); on Windows and Linux, minimize, maximize or restore, and close on the right, with close turning red on hover.
- The empty part of the bar moves the window, and a double-click maximizes it.
- The sidebar and the page are two cards on the window background, with one spacing for the window edges and the gap between them.
- The window opens in the middle of the screen at 1100 × 720 and can't be made smaller than 800 × 560. On Windows 11 its corners are rounded like other windows.
- Scrollbars are thin and in the app's colors; a touchpad swipe past the edge doesn't bounce the window.

**Layers:** frontend, `src-tauri`
**Screens and states:** title bar (light and dark, maximized and not)

### W2. Back and Forward

As a user, I go back to where I was, like in a browser.

**Acceptance criteria**
- Back and Forward move between the pages the user visited: Beranda, Riwayat, and each Tool page. Settings and changes inside a Tool page are not steps.
- A new page after Back drops the Forward steps; opening the page already on screen adds no step. The steps live only while the app is open.
- Leaving a Tool page this way asks first, like any other way out (L1, L2); staying keeps the steps as they were. Forward to a Tool page opens it empty.
- Back and Forward are dimmed when there is nowhere to go.
- Alt+← and Alt+→ (Cmd+[ and Cmd+] on macOS), the mouse's side buttons, and Escape on a Tool page (Back only) do the same.

**Layers:** frontend, `src-tauri` (macOS menu)
**Screens and states:** title bar with Back dimmed; leave confirmation from Back

### W3. Hide the sidebar

As a user, I give the page the whole window when I want it.

**Acceptance criteria**
- The title bar button, or Ctrl+B (Cmd+B on macOS), hides the sidebar and shows it again; the page card takes the freed width.
- The choice is remembered between launches.
- The button only appears where the sidebar does (768 px wide and up).

**Layers:** frontend, `src-tauri` (macOS menu)
**Screens and states:** sidebar hidden
