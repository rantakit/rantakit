# v0.4 More Tools: stories

The stories for [v0.4 More Tools](../../ROADMAP.md#v04-more-tools), grouped by epic in the order they are built. Each story is a vertical slice that can be tested on its own. Product rules come from [RANTAKIT.md](../../RANTAKIT.md), words from [GLOSSARY.md](../../GLOSSARY.md), and code boundaries from [ARCHITECTURE.md](../../ARCHITECTURE.md).

Every story has acceptance criteria, the layers it touches, the screens and states it needs designed, and its platforms. From v0.4 every Tool ships on Windows, Linux, and Android in the same release, so every story below is **Platforms: Windows, Linux, Android** unless it says otherwise.

Each Tool epic still starts with a short grilling that decides its Advanced options and error messages (ROADMAP.md). The stories below give the main options and name the Advanced options already decided; the rest are settled then.

Decisions made while writing these stories (2026-11-07):

- Every Tool keeps the three-step layout (L1–L3 in v0.2). Atur Halaman PDF (arrange PDF pages) uses its page grid as the Options step; the crop editor and the camera open full screen over the Tool page and return to the Files step.
- Every PDF Tool shows real page thumbnails, rendered with `hayro`. Measuring `hayro` moves from the PDF ke JPG (PDF to JPG) epic to the start of v0.4 (X1).
- Pisah PDF (split PDF) takes pages by range and makes several files; Atur Halaman PDF is visual and always makes one file. Extracting pages lives in Pisah PDF.
- When one Original gives several Results, they go into a new folder named after it, such as `ijazah (pages)/` (X3). This rule is added to RANTAKIT.md.
- Scan Dokumen (scan document) is JPG ke PDF with the camera as the source of files, and shares its file list, crop editor, and options.
- The camera is Rantakit's own (CameraX), not ML Kit Document Scanner, which needs Google Play Services and downloads its model ([ADR 0001](../adr/0001-files-never-leave-the-device.md)). Edges are found on each photo after it is taken, not live, so it stays light on low-end phones.
- A watermark is diagonal text repeated over the whole photo or page by default, because a single line in a corner is easy to cut off.
- HEIC and WebP are accepted by every photo Tool; their Results are JPG unless PNG is chosen.
- Kompres Dokumen (compress office documents) has the same two modes as Kompres PDF.
- Gabung PDF (merge PDF), JPG ke PDF, and Scan Dokumen make one Result from several files. On desktop it is saved next to the first file in the list, or in the folder from Settings.
- Design happens on one Claude Artifact board, "Rantakit v0.4", that draws only the new screens, at desktop and phone width; light first, dark checked at the end.

## 1. Shared pieces

### X1. PDF pages as thumbnails

**Capability:** every PDF Tool can show what each page looks like.

**Acceptance criteria**
- `rantakit-pdf` renders a page to a small image with `hayro`. The work starts by measuring `hayro` without its embedded CJK character maps and checking it on real Indonesian PDFs (scans, ijazah, KK, forms exported from Word); the fallback if it fails them is decided then (Android's `PdfRenderer` plus a fix to `hayro`).
- The APKs, the Windows installer, and the Linux `.deb` stay within the size budget ([ADR 0009](../adr/0009-size-budget.md)).
- Thumbnails render in the background, the visible pages first. A page not rendered yet shows as a numbered box, so a 200-page PDF opens at once.
- A thumbnail keeps the page's own white, with a thin border, in light and dark themes; pages are never inverted.
- A screen reader reads each thumbnail as "Halaman 3 dari 12" (Page 3 of 12), plus "diputar 90°" (rotated 90°) or "dipilih" (selected) when that applies.

**Layers:** `rantakit-pdf`, `src-tauri`, frontend
**Screens and states:** page thumbnail (rendered, not rendered yet, selected, rotated)

### X2. Files in an order I choose

**Capability:** Tools that make one Result from several files let the user set their order.

**Acceptance criteria**
- Used by Gabung PDF, JPG ke PDF, and Scan Dokumen. The first order is the order the files were chosen in.
- Each row has a drag handle, on desktop and on a phone.
- Each row's menu also has "Naikkan" (Move up) and "Turunkan" (Move down), so the order can be changed with a keyboard or a screen reader. A move is announced, such as "Dipindah ke posisi 2" (Moved to position 2).
- Rows for PDFs show the first page's thumbnail and the page count; rows for photos show the photo.

**Layers:** frontend
**Screens and states:** ordered file list (desktop and phone; while dragging; row menu open)

### X3. Several Results from one file

**Capability:** a Tool can make many files from one Original without scattering them.

**Acceptance criteria**
- When one Original gives several Results (Pisah PDF, PDF ke JPG), they are written into a new folder named after it: `ijazah (pages)/` next to the Original on desktop, or in the folder from Settings, and `Download/Rantakit/ijazah (pages)/` on Android. A taken name gets a number, as Results do: `ijazah (pages) (2)/`.
- The Result shows one summary, such as "12 file dibuat" (12 files made), the list of files, each of which opens, and "Buka folder" (Open folder) and "Bagikan semua" (Share all). On Linux, Share is left out, as everywhere.
- History keeps the Task as one entry, such as "Pisah PDF · ijazah.pdf → 3 file" or "Gabung PDF · 5 PDF → merged 2026-11-07.pdf". Opening it lists the Results, with "Buka folder" and "Bagikan semua".

**Layers:** `rantakit-tasks`, `src-tauri`, frontend
**Screens and states:** Result with many files from one file (desktop and phone); History entry with many Results, closed and open

### X4. A Result summary that fits the Tool

**Capability:** each Tool says what happened in the words that matter for it.

**Acceptance criteria**
- Each Tool sets its own summary line on the Result:
  - Compress Tools keep the size before and after (L3 in v0.2).
  - Gabung PDF: "5 PDF → 1 PDF, 23 halaman" (5 PDFs → 1 PDF, 23 pages), with the first page's thumbnail.
  - Beri Watermark (add a watermark): the Result's thumbnail.
  - Hapus Info Lokasi (remove location info): "Lokasi dan info kamera dihapus dari 3 foto" (Location and camera info removed from 3 photos).
- Every other Tool's summary is drawn on the design board with its Tool.

**Layers:** frontend
**Screens and states:** Result summary for each Tool

### X5. The Tools that fit, and finding them

**Capability:** shared, dropped, and opened files lead only to Tools that can take them, and search finds the new Tools by the words people type.

**Acceptance criteria**
- The file-first flow (H5, H6 in v0.2; F2 in v0.3) offers:
  - For PDFs: Kompres PDF, Pisah PDF, PDF ke JPG, and Beri Watermark; Gabung PDF only with 2 PDFs or more; Atur Halaman PDF only with exactly 1 PDF.
  - For photos: Kompres Foto, Ubah Format Foto, Ubah Ukuran Foto, JPG ke PDF, Beri Watermark, and Hapus Info Lokasi.
  - For Word, Excel, and PowerPoint files: Kompres Dokumen.
- Recently used Tools come first, then the rest in catalogue order.
- Search finds each new Tool by its name and these words: "tanda air" (Beri Watermark); "satukan", "merge" (Gabung PDF); "pindai", "foto dokumen" (Scan Dokumen, on Android); "heic", "webp" (Ubah Format Foto); "word", "excel", "ppt" (Kompres Dokumen).
- Each Tool's "Segera hadir" (Coming soon) card disappears when it ships (H2 in v0.2).

**Layers:** `rantakit-tasks` (file matching), frontend
**Screens and states:** matching Tools for PDFs, photos, and office documents

## 2. Arrange PDF

### M1. Gabung PDF

As a job applicant, I put my CV, ijazah, and transcript into the one PDF a portal asks for.

**Acceptance criteria**
- Accepts PDF only; photos belong to JPG ke PDF.
- Files are ordered with X2. There are no options in v0.4: the Options panel shows a summary, "5 PDF · 23 halaman" (5 PDFs · 23 pages), and the main button "Gabungkan" (Merge).
- The Result is named `merged 2026-11-07.pdf`, with today's date.
- A password-protected PDF ends the Task before anything is written, naming that file.

**Layers:** `rantakit-pdf`, `rantakit-tasks`, frontend
**Screens and states:** Gabung PDF page (empty, with files, working); Result

### M2. Pisah PDF

As a user, I take only the pages a form asks for out of a longer PDF.

**Acceptance criteria**
- Accepts one PDF or several; the same options apply to each.
- Main options:
  - *Ambil halaman* (Take pages, the default): ranges such as `1-3, 5` become one PDF, `ijazah (pages 1-3, 5).pdf`.
  - *Pisah semua halaman* (Split every page): one PDF per page, `ijazah (page 1).pdf`, in the folder from X3.
- With one PDF, the range field sits above a strip of page thumbnails. Tapping a thumbnail adds or removes it from the range, and typing a range selects the thumbnails; the two always agree.
- With several PDFs, only the range field is shown. A page that a PDF does not have is skipped, with a note on that file's row.
- Advanced options: *Setiap N halaman* (Every N pages), giving `ijazah (pages 1-5).pdf`, `ijazah (pages 6-10).pdf`, and so on.
- The main button is "Pisahkan" (Split).

**Layers:** `rantakit-pdf`, `rantakit-tasks`, frontend
**Screens and states:** Pisah PDF page (one PDF with thumbnails, several PDFs, range that does not fit); Result with one and many files

### M3. Atur Halaman PDF

As a user, I turn the upside-down pages of a scan the right way, drop the blank ones, and fix the order.

**Acceptance criteria**
- One PDF per Task. Choosing another PDF asks whether to replace the current one.
- The Options step is the page grid (X1): 2 columns on a phone, 3 on a phone turned sideways, and as many as fit on desktop, where it takes the place of the Options panel and the rest of the width.
- Every thumbnail has a checkbox that is always visible; there is no long press.
- With pages selected, a toolbar offers "Putar kiri" (Rotate left), "Putar kanan" (Rotate right), and "Hapus" (Delete). On a phone it replaces the main button at the bottom, with "Batal pilih" (Clear selection); when nothing is selected, "Simpan PDF" (Save PDF) comes back.
- Pages are reordered by dragging. On desktop, Ctrl+Z undoes, Delete deletes the selected pages, and the arrow keys move them.
- "Urungkan" (Undo) is always shown, in the top bar on a phone, and goes back one change at a time.
- Leaving with changes not saved asks first, like every other way out (L1 in v0.2).
- Every change is applied only to the Result, `ijazah (edited).pdf`; the Original stays untouched.

**Layers:** `rantakit-pdf`, `rantakit-tasks`, frontend
**Screens and states:** page grid (desktop and phone; nothing selected; pages selected; while dragging; after a delete with Undo; leave confirmation)

## 3. Paper → PDF

### D1. Crop and straighten

**Capability:** a photo of a document becomes a clean, straight page.

**Acceptance criteria**
- The edges of the document are found automatically on each photo; the file list shows the photo already cropped.
- Tapping a photo opens the editor full screen, with four corners to drag. Dragging a corner on a phone shows a magnifier, so the finger does not hide the edge.
- The four corners straighten the perspective too; there is no tilt slider.
- The editor also has "Putar" (Rotate, 90°) and "Pakai foto utuh" (Use whole photo), for when the automatic crop is wrong.
- "Selesai" (Done) applies the crop; going back drops the changes made in the editor.

**Layers:** `rantakit-image`, frontend
**Screens and states:** crop editor (desktop and phone; edges found; edges not found; dragging a corner)

### D2. JPG ke PDF

As a user, I turn three photos of my KK (family card) into one PDF.

**Acceptance criteria**
- Accepts JPG, PNG, HEIC, and WebP. Photos are ordered with X2 and cropped with D1.
- Main option: "Ukuran kertas" (Paper size): A4 (the default), F4 (Folio, common in Indonesia), or "Ikuti ukuran foto" (Match photo size).
- Pages are upright or sideways to match each photo, which is fitted whole with a thin margin.
- All photos go into one PDF, `scan 2026-11-07.pdf`.
- The main button is "Buat PDF" (Make PDF).

**Layers:** `rantakit-image`, `rantakit-pdf`, `rantakit-tasks`, frontend
**Screens and states:** JPG ke PDF page (empty, with photos, working); Result

### D3. The camera

**Platforms:** Android

**Capability:** Rantakit can take photos of paper pages itself.

**Acceptance criteria**
- The camera is Rantakit's own, built on CameraX; nothing from Google Play Services is used, and nothing is downloaded.
- The screen has a large shutter button, a flash switch, the last page's thumbnail with the number of pages taken ("3"), "Dari Galeri" (From Gallery) to add photos already taken, and "Selesai" (Done). Tapping the thumbnail opens the list of pages.
- There is no automatic capture.
- Before the camera permission is asked for, one screen says why. If it is refused, a message says how to allow it in the phone's Settings, and "Dari Galeri" still works.
- The photos taken are used only for the PDF; they are not saved to Gallery and are removed when the Task ends or is left.

**Layers:** Kotlin camera plugin, `src-tauri`, frontend
**Screens and states:** camera permission reason; permission refused; camera (no pages yet, pages taken, flash on)

### D4. Scan Dokumen

**Platforms:** Android

As a phone user, I scan the pages of a paper document into one clean PDF.

**Acceptance criteria**
- The flow is: camera (D3), then "Selesai", then the list of pages (X2, D1), then the options, then the Result.
- The options are those of JPG ke PDF, plus "Tampilan" (Look): "Bersihkan" (Clean up, the default: whiter background, stronger contrast) or "Warna asli" (Original colors). How clean-up works on low-end phones is decided at the start of the epic.
- The Result is `scan 2026-11-07.pdf` in `Download/Rantakit/`.
- The main button is "Buat PDF" (Make PDF).
- "Scan Dokumen" appears on Android only (H2 in v0.2).

**Layers:** `rantakit-image`, `rantakit-pdf`, `rantakit-tasks`, frontend
**Screens and states:** list of scanned pages; options with "Tampilan"; Result

## 4. Share safely

### K1. Beri Watermark

As a user, I put "Hanya untuk verifikasi Bank X" (Only for Bank X verification) on a copy of my KTP (ID card) before I send it.

**Acceptance criteria**
- Accepts photos (JPG, PNG) and PDFs, one kind per page: photos added to a page of PDFs, or the other way round, are refused with "Foto dan PDF tidak bisa diproses bersamaan" (Photos and PDFs can't be processed together). HEIC and WebP come with O1.
- Main options: the text, with a ready example, "Hanya untuk verifikasi …" (Only for verification of …), and the switch "Tambahkan tanggal hari ini" (Add today's date), which adds a date such as "07/11/2026" on a second, smaller line.
- With no text, the main button can't be pressed and says "Tulis teks watermark dulu" (Write the watermark text first).
- The watermark is semi-transparent text slanted at 30°, repeated over the whole photo or every page.
- A live preview of the first file (the photo, or the first page of a PDF) changes as the user types: in the Options panel on desktop, above the options on a phone.
- Advanced options, each a row of choices: "Posisi" (Position: "Berulang" repeated, "Tengah" one slanted block in the center, "Pojok kanan bawah" one straight block in the bottom right corner), "Transparansi" (Transparency: "Samar", "Sedang", "Jelas"), "Ukuran" (Size: "Kecil", "Sedang", "Besar", relative to the shorter side), and "Warna" (Color: "Abu-abu", "Hitam", "Putih", "Merah").
- On a PDF the watermark is a text layer over each page, which keeps the pages' own text sharp and selectable. Photos are turned upright first, keep no photo info, and keep their format (JPG at quality 92).
- The last text is remembered like other options, and Presets work here.
- Results are named `ktp (watermarked).jpg` and `ktp (watermarked).pdf`.
- The main button is "Beri watermark" (Add watermark).

**Layers:** `rantakit-image`, `rantakit-pdf`, `rantakit-tasks`, frontend
**Screens and states:** Beri Watermark page (photo preview, PDF preview, empty text); Result

### K2. Hapus Info Lokasi

As a user, I send a photo without telling anyone where it was taken.

**Acceptance criteria**
- Accepts JPG and PNG; HEIC and WebP come with O1, and become JPG.
- Each file row says what was found, such as "Ada lokasi · Ada info kamera" (Has location · Has camera info), or "Ada info foto lain" (Has other photo info) when there is neither.
- A photo with nothing to remove says "Sudah bersih, tidak diubah" (Already clean, not changed) and gets no Result, like a file already in the chosen format (T2 in v0.2).
- Every piece of photo info is removed except the orientation, which stays as the only tag, so the photo still shows the right way up. The picture itself is copied byte for byte, so nothing is lost.
- JPG: EXIF, XMP, IPTC, comments, extra pictures, and anything after the picture are removed; the color profile stays. PNG: EXIF, text, and the time are removed; the color chunks stay.
- Results are named `foto (cleaned).jpg`.
- The main button is "Hapus info" (Remove info).

**Layers:** `rantakit-image`, `rantakit-tasks`, frontend
**Screens and states:** Hapus Info Lokasi page (info found, already clean); Result

## 5. More formats

### O1. HEIC and WebP photos

As a user, I use the iPhone photos I get on WhatsApp like any other photo.

**Acceptance criteria**
- Kompres Foto, Ubah Format Foto, Ubah Ukuran Foto, JPG ke PDF, Beri Watermark, and Hapus Info Lokasi accept HEIC and WebP.
- Their Results are JPG unless PNG is chosen. In Kompres Foto, "same as the Original" gives JPG for these files, and transparent parts go on white.
- Ubah Format Foto converts HEIC and WebP to JPG or PNG; they are never "already JPG".
- Hapus Info Lokasi and Beri Watermark make them again as a JPG at quality 92, upright. A HEIC or WebP with no photo info is "Sudah bersih, tidak diubah".
- An animated WebP, such as a WhatsApp sticker, gives its first frame.
- Every photo Result keeps the Original's color profile, such as an iPhone's Display P3, so colors don't fade; this holds for JPG and PNG too.
- The pickers, drops, and Android's share sheet take `.heic`, `.heif`, and `.webp`, and the accepted formats read "JPG, PNG, HEIC, atau WebP".
- The decoders build from source for every platform ([ADR 0005](../adr/0005-dependency-policy.md)) and stay within the size budget.

**Layers:** `rantakit-image`, frontend
**Screens and states:** none beyond the existing Tool pages

### O2. PDF ke JPG

As a user, I send one page of a PDF as a photo, because the form only takes images.

**Acceptance criteria**
- Accepts one PDF or several.
- Main options:
  - Pages: "Semua halaman" (All pages, the default) or "Pilih halaman" (Choose pages), with the page picker from M2.
  - "Ketajaman" (Sharpness): "Standar" (Standard, the default) or "Tajam" (Sharp). The DPI number appears only in Advanced options.
- Results are named `ijazah (page 1).jpg`; several pages from one PDF go into the folder from X3.
- The main button is "Ubah ke JPG" (Convert to JPG).

**Layers:** `rantakit-pdf`, `rantakit-tasks`, frontend
**Screens and states:** PDF ke JPG page; Result with one and many files

### O3. Kompres Dokumen

As an office worker, I make a Word, Excel, or PowerPoint file small enough to email.

**Acceptance criteria**
- Accepts Word, Excel, and PowerPoint files (`.docx`, `.xlsx`, `.pptx`). Whether the older `.doc`, `.xls`, and `.ppt` are accepted is decided at the start of the epic.
- Main options: *Sesuaikan batas ukuran* (the default) and *Kecilkan saja*, as in Kompres PDF (C1, C2 in v0.2).
- File rows say "3 dokumen" (3 documents), and the picker says "Pilih dokumen" (Choose documents).
- Results are named `laporan (compressed).docx`.
- The main button is "Kompres" (Compress).
- It stays within the size budget.

**Layers:** new engine crate or `rantakit-pdf` (decided at the start of the epic), `rantakit-tasks`, frontend
**Screens and states:** Kompres Dokumen page

## Screens to design

Every screen and state the stories above need, at desktop and phone width, Indonesian first, in light; dark is checked at the end. They are drawn in this order:

1. **Shared pieces:** page thumbnail (X1); ordered file list (X2); Result with many files, and its History entry (X3)
2. **Editors:** Atur Halaman page grid (M3); crop editor (D1); camera and its permission screens (D3)
3. **Watermark:** Beri Watermark page with its live preview (K1)
4. **Each Tool:** the pages and Result summaries of Gabung PDF, Pisah PDF, JPG ke PDF, Scan Dokumen, Hapus Info Lokasi, PDF ke JPG, and Kompres Dokumen (X4)
